## Why this matters

Analysts increasingly work next to data scientists and use tools that contain machine learning. You do not need to build models at this level. You need to understand the vocabulary, ask good questions and avoid the most common traps.

## Learning from examples

In classic software, a person writes the rules. In machine learning (ML), a method looks for patterns in example data and builds a model that makes predictions or groups for new cases. The model is only as good as the examples it saw.

## Supervised and unsupervised learning

- Supervised learning: the examples come with known answers, called labels. The model learns to predict the label from the other columns, the features. Typical tasks: predict whether a customer will cancel (classification) or predict next month's sales (regression).
- Unsupervised learning: there are no labels. The method looks for structure on its own. A typical task is clustering, for example grouping customers with similar behaviour.

## Training and test data

If you check a model on the same data it learned from, the result looks better than it will be in real life. So you split the data. The training set is used to build the model. The test set is kept aside and used once, at the end, to estimate how the model performs on cases it has never seen.

## Overfitting

A model overfits when it learns the quirks and noise of the training data instead of the general pattern. Warning sign: it does very well on training data and clearly worse on test data. A simpler model, more data or fewer irrelevant features often helps.

## AI assistants as helpers

Chat-based AI assistants can draft SQL, suggest chart types or explain an error message. They write fluent text, but they can state wrong things with confidence. Treat the output as a draft from a colleague who has not seen your data: run the query, check the numbers against a source you trust and never paste confidential or personal data into a tool your organisation has not approved. Responsibility for the result stays with you.

## Worked example

Illustration only; invented scenario. A team wants to predict which customers will cancel. They have 10,000 past customers, each with a known outcome. This is supervised learning, because the outcome is a label. They put 8,000 customers into the training set and keep 2,000 aside. The model scores very well on the 8,000 but clearly worse on the 2,000, which is a sign of overfitting. They simplify the model, check again on the test set and report the test result, not the training result. Separately, an analyst asks an AI assistant for a SQL query; the analyst reads it, runs it on a small sample and compares the totals with an existing report before using it.

## Key takeaways

- ML learns patterns from examples; supervised learning uses labels, unsupervised learning does not.
- Judge a model on test data it has not seen, never on training data.
- Strong training results with weak test results point to overfitting.
- AI assistants help with drafts, but you verify every result and protect confidential data.
