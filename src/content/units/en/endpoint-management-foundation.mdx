## Why this matters

Almost every support request involves a device: a laptop that will not start, a printer that is not found, a program that needs an update. A new colleague who gets a working device on day one starts productively; one who waits two days does not. Knowing how a device is built up, and setting it up in a repeatable way, is a core skill of IT support.

## The operating system

An **operating system** is the software that manages the hardware of a device and provides common services to programs. It starts the device, manages memory and storage, controls access to peripherals and shows the user interface. Programs do not talk to the hardware directly; they ask the operating system. Common examples are Windows, macOS and Linux on computers, and Android and iOS on phones and tablets. As support staff you should know which operating system and which version a device runs, because instructions, available software and security updates depend on it.

## Installing and updating software

- Install only from **trusted sources**: your organisation's software catalogue or the vendor's official site. Software from random download pages can contain unwanted or harmful code.
- Check that you are allowed to install it and that the licence covers the use. Many programs are paid or limited to certain uses.
- Note the version you install, so you can find it again later.

A **patch** is a change to a program that fixes errors, closes security gaps or improves it. Applying updates promptly is one of the simplest and most effective protections, because attackers often use gaps that are already known and fixed. Updates can also change behaviour, so tell users when a restart is needed and ask them to save their work first.

## A device setup checklist

A checklist makes setup repeatable and prevents forgotten steps:

1. Unpack and check the device and its accessories; note the asset or serial number.
2. Install operating system updates.
3. Create the user account as agreed; do not share one account between people.
4. Install the standard software.
5. Connect to the network and the printer; check that mail and shared folders work.
6. Check that security settings are on (see the next levels).
7. Let the user test with their own tasks and hand over with a short explanation.

## Peripherals

Peripherals are devices connected to the computer: monitor, keyboard, mouse, headset, docking station, printer. When something does not work, check the simple things first: is the cable seated, is the device switched on, does the operating system list it, is the right device selected as default in the settings? A driver is the small piece of software that lets the operating system use a specific device; many common devices work without a separate installation.

## Worked example

A new employee, Mr Kaya, starts on Monday. You unpack the laptop, note the serial number in the asset list, run the operating system updates, create his account and install the standard software from the catalogue. You connect the docking station with two monitors, test sound on the headset and print a test page. Finally you let him sign in himself and open his mailbox. Everything is ticked on the checklist, so a colleague could repeat it identically.

## Key takeaways

- The operating system manages hardware and provides services to programs; know the version of each device.
- Install software only from trusted sources and keep it updated; patches close known gaps.
- Use a checklist for every device setup.
- For peripherals check cable, power, detection by the system and default selection first.
